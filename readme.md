Selling travel is a chain of small, error-prone tasks: holding seats with airlines, registering passengers,
collecting deposits, chasing ticketing deadlines, answering quote requests, keeping track of who is on leave.
Most agencies juggle spreadsheets, e-mails and several disconnected tools to do it.

**Template Travel Company** puts the whole chain in a single web application. Sales agents sell and follow up
bookings; managers run the catalogue, the agencies, the team and the brand. It ships as clean, tested Laravel
source code: deploy it as it is, rebrand it in minutes, or extend it into your own product.

> [!NOTE]
> Everything you see in this README and in the demo is fictitious data generated by the included seeders.
> The interface is written in French; the application already supports a per-user locale, so adding a language
> means adding its translation file.

## Why Template Travel Company

| | |
|---|---|
| **One tool for the whole sales chain** | From the seat held with the airline to the issued ticket and the paid balance, every step lives on the same booking, with a full history of who did what. |
| **Multi-agency from day one** | Head office, branches and partner agencies share one platform. Partners only sell what they are allowed to, never see purchase prices, and only access their own bookings. |
| **No hard-coded destinations** | A destination is a row in the database. Adding a country creates its menus, its screens and its access right — no developer needed. |
| **White label** | Agency name, logos (light background, dark background, icon) and brand colours are set from the admin panel and applied everywhere instantly. |
| **Fine-grained access rights** | Each agent gets rights per destination and per module: ferries, quotes, payments, exports, allotments, procedures, team planning. |
| **Built for daily operations** | Ticketing deadline alerts, automatic option expiry, monthly leave accrual, Excel exports, PDF contracts and e-tickets, SMS quotes. |
| **Production-grade code** | Service classes, database transactions and row locks on seat inventory, 100+ server tests and an end-to-end browser suite that visits every page and submits every form. |

## Quick start

There are two ways to run the demo. Both end at **http://localhost:8000** with a complete, pre-filled data set.

### Option 1 — Docker, one command (recommended)

All you need is [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows, macOS) or Docker Engine (Linux).

```bash
git clone <repository-url> template-travel-company
cd template-travel-company          # the folder that contains docker-compose.yml
docker compose up
```

The first start builds the image (PHP 8.4 with every required extension and the Composer dependencies), starts
MySQL 8.4, creates the database, loads the demo data and prints:

```text
Template Travel Company est prêt : http://localhost:8000
```

| Command | Effect |
|---|---|
| `docker compose up` | Start the application and MySQL (demo data is created on the first start only) |
| `DEMO_RESET=true docker compose up` | Start with a fresh copy of the demo data |
| `APP_PORT=9000 docker compose up` | Serve the application on another port |
| `docker compose down` | Stop everything (data is kept) |
| `docker compose down -v` | Stop everything and delete the database |

### Option 2 — PHP on your machine

Requirements: **PHP 8.4** with Composer (the easiest way is [Laravel Herd](https://herd.laravel.com)) and Docker for MySQL only.

```bash
cp .env.example .env
docker compose up -d mysql           # MySQL 8.4 on port 3307
composer install
php artisan key:generate
php artisan jwt:secret               # signing key for the public API
php artisan migrate --seed           # schema + demo data
php artisan serve                    # http://127.0.0.1:8000
```

Reset the demo at any time with `php artisan migrate:fresh --seed`.

## Architecture

```text
                 ┌──────────────────────────────┐
  Agents ───────►│  Agent workspace   /agent    │──┐
                 ├──────────────────────────────┤  │   ┌──────────────────────┐
  Managers ─────►│  Administration    /admin    │──┼──►│  Laravel 13 (PHP 8.4)│──► MySQL 8.4
                 ├──────────────────────────────┤  │   │  services · jobs ·   │
  Website ──────►│  Public API        /api      │──┘   │  mail · documents    │──► Card payment page
                 └──────────────────────────────┘      └──────────────────────┘──► SMS gateway
```

| Layer | Location |
|---|---|
| Routes | `routes/agent.php`, `routes/admin.php`, `routes/api.php`, `routes/web.php` — one file per workspace |
| Controllers | `app/Http/Controllers/{Agent,Admin,Api,Auth}` |
| Domain services | `app/Services` — booking notifications, sales statistics, leave balances, quotes, SMS |
| Models | `app/Models` — 56 Eloquent models over 63 tables |
| Scheduled jobs | `app/Console/Commands` — ticketing alerts, allotment statuses, leave accrual, rest days |
| Branding & destinations | `app/Support/Branding` — read from the database and cached |
| Permissions | `app/Support/AgentPermissions` — destination rights generated, module rights declared once |
| Interface | `resources/views`, `public/css/tc/theme.css`, `public/js/tc/ui.js` |
| Demo data | `database/seeders/Demo` — deterministic, one seeder per domain |

Key implementation choices:

- **Seat inventory is never oversold** — seat counts change inside database transactions with row locks.
- **Configuration is cache-safe** — no `env()` call outside `config/`, so `php artisan config:cache` is safe in production.
- **Everything agency-specific is configuration or data** — notification addresses, CORS origins and departure country in `.env` (`config/agency.php`); brand and destinations in the database.
- **Heavy screens are built for speed** — team planning and leave balances run a constant number of queries whatever the team size, and the current month is embedded in the page.

## Built to scale

| Growth step | How the template handles it |
|---|---|
| **New destinations** | Added from the admin panel; menus, screens and rights follow automatically. |
| **New agencies and partners** | Agencies are data; partner rights and data isolation are built in. |
| **A bigger team** | Rights per destination and module, super agents for supervision, planning and balances computed in constant time. |

## Quality & testing

Two complementary suites, each running on its own database so that working data is never touched.

```bash
php vendor/bin/phpunit                               # server tests — database travel_company_test
cd tests/Browser && npm install && npx playwright install chromium
npm test                                             # browser tests — database travel_company_e2e
```

- **PHPUnit — 100+ tests.** Complete business flows: flight sale and follow-up, ticketing, deposits, ferries,
  allotments, quotes, leave and planning, card payment (including signature verification), public API,
  administration, single sign-in. Every form submission route of the application is called at least once.
- **Playwright end-to-end suite** (`tests/Browser`). Opens every page, follows every link with each demo account,
  submits every form and replays guided scenarios (sign-out from the profile menu, passenger edits, quotes,
  in-page documents). It reports server errors, JavaScript errors, broken links and missing images, and
  `npm run test:captures` saves a screenshot of every page.

## FAQ

<summary><strong>Can I sell destinations other than the demo ones?</strong></summary>

Yes. Destinations are data: create one in *Administration › Destinations* and its flight menus, screens and agent
right appear immediately. Nothing in the code refers to a specific country.

Yes. Mark an agency as a partner: its agents only get the destinations and modules you grant, never see purchase
prices and only open their own bookings. File management and ticketing stay with the head office.

</details>

<details>
<summary><strong>Is it only for flights?</strong></summary>

No. Ferries with vehicles, seat allotments, travel insurance, client quotes and card payments are built in, and the
structure makes other products straightforward to add.

</details>

<summary><strong>How do I put my own brand on it?</strong></summary>

Upload your logos and choose your colours in *Administration › Identité & couleurs*. Both workspaces, the sign-in
page and the e-mails pick them up instantly.

</details>

<details>
<summary><strong>Which payment provider is supported?</strong></summary>

Paybox (Verifone), including signature verification of the bank's return. The payment flow is isolated in
`App\Support\Paybox`, which makes another provider easy to plug in.

</details>

<summary><strong>Do I need anything else than Docker to try it?</strong></summary>

No. `docker compose up` builds the application image, starts MySQL, creates the database and loads the demo data.

With Docker: `DEMO_RESET=true docker compose up`. Without Docker: `php artisan migrate:fresh --seed`.
